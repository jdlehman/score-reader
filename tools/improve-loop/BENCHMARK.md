# Benchmark — score-reader self-improvement loop

The benchmark is the measurement side of the loop: a fixed page
registry, a resumable Audiveris runner, and a scorer that wraps the
existing `open_score.score`. It measures desktop Audiveris 5.11 only.
It is additive tooling: it touches nothing in `app/`, `teavm/`, or
`test/`.

Files:

| File | What it is |
| --- | --- |
| `registry.json` | One entry per benchmark page: paths + metadata only, no embedded music data. |
| `build_registry.py` | Regenerates `registry.json` from the preflight corpus + GT files + the licence/GT tables. |
| `run.py` | Runner: Audiveris + scoring, resumable/cached, one results file per run under `runs/`. |
| `score.py` | Scorer: wraps `open_score.score`, adds aggregates + baseline-vs-method comparison. |
| `audiveris.py` | Runs desktop Audiveris on one image; summarises a `.mxl`. |
| `recover.py` | Photometric recovery of one page image (`median+rl` is the shipped config). |
| `runs/` | Per-run results files (`<run-id>.json`). Gitignored. |
| `audiveris-out/` | This loop's own Audiveris outputs, `<method>/<page-id>/`. Gitignored. |
| `recovered/` | Deblur-preprocessed images generated by this loop, `<method>/<page-id>.png`. Gitignored. |

## Registry schema

`registry.json` (version 1): 44 pages — the 119-page preflight
corpus (`photometric/preflight-corpus-results.json`) filtered to the
pages this repository may hold, plus 2 writer-path extras not in
that corpus. Every entry is licence-clean (CC0 or Public Domain);
there are no `local_only` entries. The full local registry (123
pages) lives in the workspace with the local test set; this is its
committable subset.

All paths are relative to the corpus root — the local test set
directory that contains `open-music/` and `photometric/` (e.g. image
`open-music/pages/lieder-lindenbaum.png`).

Per-page entry:

| Field | Meaning |
| --- | --- |
| `id` | Stable id, e.g. `photo-lieder-lindenbaum-photo-hard`, `onepage-lieder-gute-nacht`. |
| `group` | Preflight group (`render-gute-nacht`, `render-onepage`, `photo-synthetic`, `scan`, `scan-hymnal`, `scan-organ`, `writer-path`). |
| `image` | Page image path (relative to corpus root). |
| `gt` | Ground-truth json path, or `null`. |
| `gt_kind` | `notes` (note GT, scored by `open_score`), `lyrics` (hymnal stanza-word GT), or `null` (structural metrics only). |
| `beats` | Time-signature beats from the GT (`null` for gt:null pages and the hymnal, which has no printed time signature). |
| `licence` | Short licence label — `CC0` or `Public Domain` only. |
| `local_only` | Always `false` in this registry. Any `true` is an audit failure (see `verifier_health.py`). |
| `tests` | What the page tests, e.g. "hard photo, tuplet-heavy voice+piano, lyrics". |
| `staves_preflight` | Staves detected by preflight (a measurement, not ground truth). |
| `staves_true` | True staff count where the manifest states one, else `null`. |
| `preflight_warn` / `preflight_spacing` | Preflight result if known (`null` for writer-path extras). |
| `gt_notes` / `gt_lyrics` / `gt_unpitched` | GT counts (hymnal: 375 stanza words by the scorer's tokenisation). |
| `clean_counterpart` | For photo pages: the clean page id the photo was made from. |
| `base_page` | Same as `clean_counterpart` (photo pages only). |
| `legacy_mxl` | Existing desktop `.mxl` outputs verified on disk at build time: `{"baseline": <path>, "deblur": <path>, "deblur_image": <path>}`. The runner copies these instead of re-running Audiveris. |

Counts (from `registry.json` `counts`): 29 pages with note GT, 1 with
lyrics GT (hymnal), 14 gt:null pages scored by structural metrics
only. 39 pages have a legacy baseline `.mxl`, 13 have a legacy deblur
`.mxl`, 14 have a legacy deblur image.

### Subsets (in `registry.json` `subsets`)

| Subset | Pages | Notes |
| --- | --- | --- |
| `default` | 12 | The 6 synthetic hard photos + their 6 clean counterparts. The fast default. |
| `photo-hard` / `photo-mild` / `photo-moderate` | 6 each | One severity across the 6 photo bases. |
| `photo-all` | 18 | All synthetic-photo variants. |
| `onepage` | 11 | The one-page set (10 Lieder + Beethoven finale). |
| `gute-nacht` | 4 | The full multi-page piece. |
| `scans` | 9 | Real scans: 6 `scan` + hymnal + 2 Schoen organ pages. |
| `writer` | 2 | Writer-path features (grace, octave-shift). |
| `clean` | 44 | Every page (the registry is already clean-only). |
| `all` | 44 | Everything. |

### How to add a page

1. Put the image + GT under the corpus (follow the local test set's
   manifest: record licence + source URL there). **Only CC0 and
   Public Domain, music and edition both, may be added here.** A page
   under any other licence, a testing-only encoding, or a private
   score stays in the local test set and is not named in this repo.
2. Add the licence/GT mapping to `build_registry.py` (the `ONEPAGE`,
   `PHOTO_BASES`, or `WRITER_PATHS` table, or a new branch in
   `entry_for_preflight`). The builder skips anything whose licence
   is not CC0 or Public Domain — do not add a table entry for it.
3. Run `python3 build_registry.py --corpus <dir>` and check the
   printed counts and that no `WARNING` lines appear (a warning means
   a missing image, GT, or licence). Skipped pages are printed as
   `SKIP` lines — that is the licence gate working, not an error.
4. If a legacy desktop `.mxl` already exists for the page, add its
   path to `legacy_mxl_for` in `build_registry.py` so the runner
   reuses it; otherwise the first run will run Audiveris fresh.
5. Add the page id to a subset in `build_registry.py` if it belongs
   in one (or use `--only <id>` for one-offs).

## Runner

```
python3 run.py [--subset NAME] [--only PAGE ...] [--clean-only] [--force]
               [--method METHOD] [--run-id ID] [--corpus DIR]
python3 run.py --list-subsets
python3 run.py --list-methods
```

- `--subset` defaults to `default` (12 pages). `--only` takes exact
  registry ids and overrides `--subset`.
- `--clean-only` drops `local_only` entries. The published registry
  has none, so it is a no-op here (kept as a safety net).
- `--force` re-runs Audiveris even where a `.mxl` already exists.
- `--method` picks a pipeline variant (see below). `--run-id` names
  the results file; default is `<YYYYMMDD-HHMMSS>-<method>`.
- `--corpus` names the corpus root, or set `SCORE_READER_CORPUS`.

Caching: a job whose outdir (`audiveris-out/<method>/<page-id>/`)
already holds a `.mxl` is recorded as cached (re-scored, no re-run).
On first use the runner copies a `legacy_mxl` `.mxl` from the registry
into that outdir and records `cached_from`. A failed job (no `.mxl`)
is re-attempted on the next pass. Results are written to
`runs/<run-id>.json` after every page, so a killed run resumes where
it stopped (re-running with the same `--run-id` keeps already-recorded
pages whose `.mxl` still exists).

Run file (`runs/<run-id>.json`): run id, timestamp, method, subset,
`clean_only`, environment note (hostname, Audiveris 5.11 desktop with
the no-OCR constants from `audiveris.py`, Java version), and
per-page results: `status` (`ok` / `no-output` / `error`), `cached`,
`cached_from`, `seconds`, `mxl` path, and `metrics` (see scorer).
A `summary` block counts ok / no-output / error / cached and wall
seconds. Run files are local working files (gitignored), not committed.

### Methods

Method registry lives at the top of `run.py`; add a variant by adding
one entry (`preprocess` is a `recover.py` method name, or `None` for
no preprocessing).

| Method | Pipeline |
| --- | --- |
| `baseline` | Raw image through Audiveris 5.11 desktop. |
| `deblur` | 3×3 median → Richardson-Lucy σ=1.8, 15 iters (`recover.py` `median+rl`, the shipped config), then Audiveris. |
| `rl` | Richardson-Lucy σ=1.8, 15 iters only, then Audiveris. |

Deblur preprocessing runs the vendored `recover.py` with the current
Python; if that Python lacks cv2/scipy, point `SCORE_READER_PHOTO_PY`
at a Python that has them. Generating one deblurred full page takes
~70 s; the runner therefore reuses the legacy recovered images where
they exist (14 in this registry) and only generates the missing ones.

### Expected runtimes

Audiveris desktop runs ~35–110 s per page fresh; pages that fail do
so in seconds. The default subset (12 pages) reuses cached `.mxl`
for 11 of 12 pages; only the Gute Nacht hard photo needs a fresh run.
The full `all` subset (44 pages) is hours fresh — shard with `--only`
or run subsets separately. No run here uses Gradle, emcc, or cargo.

## Scorer

```
python3 score.py <run.json> [--baseline <baseline-run.json>]
python3 score.py --mxl <path.mxl> --page <registry-id> [--corpus DIR]
python3 score.py --rescore <run.json> [--corpus DIR]
```

`score.py` imports `open_score.score` (it does not copy it) and
`audiveris.summarise_mxl`. Per-page metrics:

| Metric | Definition |
| --- | --- |
| `exact_pitch` / `exact_recall` | Per-bar multiset hits on pitch (step+octave) vs GT / GT note count. Comparison is by content, never by id offset (inherited from `open_score`/`score_all`). |
| `pitch_class` / `pitch_recall` | Same, pitch class only. |
| `note_type` | Per-bar multiset hits on note type. |
| `seq_ratio_mean` | Mean difflib sequence ratio of predicted vs GT pitch sequence, per GT part (best matching predicted part). |
| `lyric_hits` / `lyric_total` / `lyric_recall` | Note-GT pages: multiset lyric-syllable hits vs GT lyrics (Audiveris runs with OCR off, so this is 0 unless OCR is enabled — record it, do not assume it). Hymnal page: stanza-word recall (375 words) instead. |
| `measures_valid` / `measures_total` / `validity_rate` | Duration-valid (bar, voice) pairs: summed durations vs the page's time signature (`beats` from GT; 4 assumed where unknown — see `beats_assumed`). |
| `pred_notes` / `pred_parts` | Structural counts from the `.mxl`, available for every page including gt:null. |

Failed / no-output runs: metrics are 0 with `status: no-output`
(or `unscored` + `reason` if scoring itself raised). They are never
silently dropped — they count in the aggregates' `no_output` /
`unscored` columns.

`score.py <run.json>` prints per-group aggregates: n, ok / no-output /
unscored counts, mean + median exact recall, mean pitch recall, mean +
median validity rate, mean lyric recall, and how many GT pages were
scored. With `--baseline`, it also prints a per-page comparison table
(baseline vs method exact recall and validity, with deltas) and counts
of improved / regressed / unchanged / incomparable pages. A page
counts as improved/regressed only past a 0.01 exact-recall delta
(0.02 validity delta where there is no GT); anything inside is
unchanged. Read the per-page table, not just the counts — a method
can help one page and hurt another, and the aggregate hides that.

### What the numbers do not cover

- Lyrics: desktop Audiveris here runs with Tesseract OCR disabled
  (`TesseractOCR.useOCR=false`), so lyric recall is 0 on note-GT
  pages by construction. That is an environment gap, not a model
  result.
- `gt:null` pages (14) have no pitch ground truth: only structural
  metrics (note counts, validity) are meaningful for them.
- Preflight staff counts in the registry are detected counts, not
  ground truth; `staves_true` is set only where the manifest states
  a count.

## Fast path vs final check

- **Fast path (this benchmark):** desktop Audiveris 5.11 harness.
  That is what `run.py` measures. Use it for iteration: every method
  change gets a baseline-vs-method comparison on named pages here
  first.
- **Final check (manual, not faked):** the in-browser TeaVM WasmGC
  build. Nothing in this directory runs Wasm or claims Wasm parity.
  When a method graduates from the desktop harness, re-run the same
  subset against the current Wasm build by hand and record the Wasm
  run id alongside the desktop run id. A desktop win that does not
  reproduce under Wasm is not a win.

## Licence hygiene

The registry, runner, scorer, docs, and run files hold paths +
metadata + measured numbers only — no embedded music data. The
published registry holds only CC0 and Public Domain pages (music and
edition both); the generator skips anything else, and the verifier
fails the audit if any `local_only` entry appears. Run outputs are
gitignored. Pages under any other licence, a testing-only encoding,
or a private score stay in the local test set and are not named in
this repository — that is the rule in `test/corpus/README.md`, "What
may be committed", applied to this tooling.
